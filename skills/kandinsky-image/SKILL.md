# Kandinsky: генерация изображений

Сервер отдаёт **только изображения**. Видео, видео со звуком и аватар в API есть,
но инструментов под них в этой версии нет — на такие просьбы отвечайте прямо, что
это не поддерживается.

## Порядок работы

1. Не уверены в параметрах — вызовите `kandinsky_routes`: там допустимые разрешения
   и значения перечислений для каждой модели.
2. Вызовите нужный инструмент генерации.
3. Если в ответе `status` = `queued` или `processing` — задача ещё идёт. Файл
   скачивается фоновым поллером сам, повторять генерацию не нужно: вызовите
   `kandinsky_task_result` с тем же `task_id`.

## Инструменты

| Инструмент | Зачем | Обязательное |
|---|---|---|
| `kandinsky_image_generate` | Картинка по тексту | `prompt` |
| `kandinsky_image_edit` | Изменить картинку по описанию | `prompt`, `images` (1–3) |
| `kandinsky_image_upscale` | Увеличить в 2 или 4 раза (`upscale`, плюс `creativity` 0..8 — сила перерисовки) | `image` |
| `kandinsky_task_status` | Состояние задачи | `task_id` |
| `kandinsky_task_result` | Забрать готовый файл | `task_id` |
| `kandinsky_tasks_list` | История генераций | — |
| `kandinsky_routes` | Справка по моделям и параметрам | — |

## Обязательный результат: файл в сессии + ссылка в канвасе

Задача не считается выполненной, пока сгенерированная картинка не вернулась
пользователю **в файл сессии** и пока в **канвасе** (или финальном ответе, если
канваса нет) не показана ссылка.

В GigaCowork файл забирается платформой по `structuredContent.download_url`
(аннотация `x-session-file-output: url`; проверено — после генерации платформа
делает GET `/files/...`). Всё равно проверь, что файл появился в сессии.

1. после генерации дождись `saved` или вызови `kandinsky_task_result(task_id)`;
2. убедись, что файл в сессии есть; если нет — сохрани его доступным
   инструментом записи: байты из `kandinsky_task_result(task_id,
   return_base64=true)` или загрузка по ссылке `download_url`, если клиент умеет
   качать URL; имя — `<task_id>.<ext>`, сверь `bytes` и `sha256`;
3. в канвас/финальный ответ обязательно выведи кликабельную ссылку
   `download_url` (она есть в тексте ответа) и превью;
4. если файл в сессию сохранить не удалось — не заканчивай ответ молчанием:
   укажи причину и всё равно отдай ссылку и превью.

Запрещено завершать ответ формулировкой «файл лежит на сервере» без файла в
сессии и без ссылки в канвасе.

Для клиентов без файлового расширения (например, DSH) вызови
`kandinsky_task_result(task_id, return_base64=true)` и возьми
`structuredContent.media[].b64`, затем декодируй и запиши в файл. Проверь, что
`len(data)` совпадает с `bytes`, а `sha256` — с `sha256` из ответа. Если
`b64_error=file_too_large`, файл больше 4 МБ — скачивай по `download_url`.

Рабочая последовательность:

1. `kandinsky_image_generate(prompt, wait_seconds=0)` → `task_id`
2. `kandinsky_task_status(task_id)` повторять до `saved`
3. `kandinsky_task_result(task_id, return_base64=true)` → `media[].b64` в `structuredContent`
4. декодировать base64 → проверить длину и sha256 → записать файл в сессию
5. вывести в канвас/ответ ссылку `download_url` и превью
6. сообщить пользователю, что файл готов

`b64` отдаётся только для файлов до 4 МБ. Картинка 1024×1024 в JPEG — это
150–300 КБ, base64 от неё ~1.37×, запас большой. Не влезает — вернётся
`b64_error: "file_too_large"`, тогда используйте `download_url`.

`kandinsky_task_result` читает файл с диска и в API не ходит, поэтому повторные
вызовы безопасны и квоту не тратят.

## Редактирование картинки из файлов сессии

Сервер работает на другой машине и **не видит** файлы сессии агента
(`/session/...`). Если передать такой путь в `images`, придёт ошибка — это
**не повод перегенерировать картинку**, хотя соблазн есть.

Три рабочих способа передать изображение:

1. **Картинка получена от этого же сервера** — передайте её `path` из ответа
   (`results/2026-10-24/3797.jpg`) или ссылку `media[].url`. Сервер прочитает
   файл из своего хранилища, гонять base64 не нужно.
2. **Своя картинка в сессии** — прочитайте и закодируйте у себя:

   ```python
   import base64
   b64 = base64.b64encode(open("/session/cat_dog.jpg", "rb").read()).decode()
   ```

   и передайте в `images: [b64]`. Для JPEG 182 КБ это ~243 КБ строки.
3. **data-URI** — `data:image/jpeg;base64,…`.

Если картинка больше ~4 МБ, сначала уменьшите её (Pillow) — иначе аргумент
инструмента станет слишком большим и сервер всё равно ужмёт её до лимита
маршрута.

## Модели

| Инструмент | `model` | Что это |
|---|---|---|
| `generate` | `k6` (по умолчанию) | Kandinsky 6, быстрее |
| `generate` | `k5` | Kandinsky 5 |
| `edit` | `k6` (по умолчанию) | Обычная модель |
| `edit` | `kandishop` | Квантованная, легче |

`kandinsky_image_upscale` выбора модели не имеет.

Чем отличаются:
- **k6**: `beautificator` = `enabled` / `disabled` / `gigachat-max`; разрешение `auto` доступно.
- **k5**: `guidance` (по умолчанию 3.5), `use_original_prompt` (по умолчанию `false`),
  разрешение `512x512` доступно. Параметра `beautificator` нет.

Если передать параметр не от той модели, он будет отброшен, а в ответе появится
`warnings` — это не ошибка.

## Важные параметры

- `prompt` — до 2048 символов.
- `resolution` — `1024x1024`, `768x768`, `768x1280`, `1280x768`, `auto`; у k5 ещё `512x512`.
  Разделитель `:` тоже принимается (`1280:768`).
- `censor` — по умолчанию включён. Не выключайте без причины.
- `wait_seconds` — сколько секунд ждать результат внутри вызова. Можно просить
  любой (даже 90) — это не ошибка: сервер обрежет ожидание общим бюджетом
  `CALL_BUDGET_SECONDS` (45 с от начала вызова, включая создание задачи).
  `0` — только создать задачу и сразу вернуть `task_id`. k5 обычно укладывается
  в бюджет, k6 (~90 с) — нет: для него штатный путь — `task_id` и
  `kandinsky_task_result`. Если создание задачи заняло много времени, сервер
  вернёт `task_id` раньше — не повторяйте генерацию.
- `images` / `image` — base64, `data:`-URI или путь к файлу (путь только в stdio-режиме).
  В GigaCowork вместо них платформа подставляет `read_url` (файл сессии).
  Слишком большие картинки сервер уменьшает сам и сообщает в `warnings`.

## Правила, которые экономят квоту

Один запрос — одна генерация. Дольше ждём, но повторно не генерируем.

1. **Не повторяйте одинаковый вызов.** Сервер сам вернёт ту же задачу и добавит
   предупреждение: повтор в течение 90 секунд не создаёт новую генерацию. С
   02.11.2026 это работает и между моделями: попросили k5, пока k6 ещё считается,
   — вернётся задача k6, второй генерации не будет.
2. **Вернулся `task_id`, а не картинка** — не генерируйте заново и не переключайте
   модель, забирайте результат через `kandinsky_task_result(task_id)`. Повторный
   `generate` вместо опроса — это вторая платная генерация.
3. **Квота k6 кончилась** (`quota_monthly`) — один повтор с `model="k5"`, промпт и
   остальные параметры те же. Менять промпт на повторе нельзя: подпись запроса
   изменится, дедуп не сработает и уйдёт лишняя генерация.
4. **Для черновиков и серий берите k5.** Месячный лимит k6 обычно заметно меньше,
   а считается он дольше (~90 с против ~38 с).
5. **Нужна вторая картинка по тому же промпту** — передайте `force_new: true`.
6. **`kandinsky_task_result` безопасно вызывать сколько угодно раз**: он читает файл
   с диска и в API не ходит. Результат в API одноразовый, но наша копия — нет.

`GET /stats` (с `X-API-Key`) показывает расход за месяц по маршрутам. Поле `quota`
там — последний известный отказ по квоте; после успешной генерации оно
сбрасывается, так что отсутствие поля значит «неизвестно», а не «ноль».

## Ошибки и что с ними делать

| Код | Действие |
|---|---|
| `censored` | Переписать промпт. Повтор того же бесполезен |
| `prompt_too_long` | Сократить описание |
| `input_too_large`, `input_bad_resolution` | Сильно пережать или взять картинку меньше |
| `quota_monthly` | Один повтор с `model="k5"` (промпт тот же). Если и там `quota_monthly` — лимит исчерпан на месяц, ждать сброса |
| `quota_daily` | Дневной лимит исчерпан, ждать сброса |
| `quota_concurrent`, `quota_rate` | Подождать, повторить позже |
| `censor_unavailable` | Цензор недоступен, повтор имеет смысл |
| `auth_failed` | Неверный ключ, проблема на стороне настройки сервера |
| `not_ready` | Ещё идёт, повторить позже |

## Что приходит в ответе

Текстовая часть — короткая сводка со ссылкой (её читает модель):

```
task_id=3797, status=saved, model=k6-image-t2i; файл: 3797.jpg, image/jpeg, 101751 Б, sha256=78fa0d54…
download_url: https://kandinsky.example.com/files/results/2026-10-24/3797.jpg?exp=…&sig=…
```

Машинные данные лежат в `structuredContent`:

```json
{
  "task_id": "3797",
  "status": "saved",
  "model": "k6-image-t2i",
  "elapsed_ms": 16000,
  "filename": "3797.jpg",
  "content_type": "image/jpeg",
  "download_url": "https://kandinsky.example.com/files/results/2026-10-24/3797.jpg?exp=…&sig=…",
  "size": 101751,
  "media": [{
    "filename": "3797.jpg",
    "mime": "image/jpeg",
    "bytes": 101751,
    "sha256": "78fa0d54…",
    "url": "https://kandinsky.example.com/files/results/2026-10-24/3797.jpg?exp=…&sig=…",
    "path": "results/2026-10-24/3797.jpg"
  }],
  "next": "Файл готов: filename, размер и download_url — в ответе; ссылка живёт 7 дней."
}
```

- Картинка приходит **превью прямо в ответе** (по умолчанию без ограничения по
  размеру; `MAX_INLINE_RESULT_CHARS` может задать бюджет).
- `download_url` — подписанная HTTPS-ссылка, она продублирована в тексте: так
  GigaCowork-агент может отдать ссылку пользователю, даже если файл не попал в
  сессию.
- `status` = `failed` — смотрите `error`, повтор без изменений бесполезен.

## Примеры

Сгенерировать по умолчанию:

```json
{"prompt": "рыжий кот на подоконнике, утренний свет, акварель"}
```

Маленький черновик на k5 без LLM-переписывания промпта:

```json
{"prompt": "кот", "model": "k5", "resolution": "512x512", "use_original_prompt": true}
```

Пропорции под вертикаль с переписыванием промпта:

```json
{"prompt": "маяк на скале", "model": "k6", "resolution": "768x1280",
 "beautificator": "gigachat-max"}
```

Изменить присланную картинку:

```json
{"prompt": "сделать акварелью", "images": ["<base64 или data:URI>"], "model": "k6"}
```

Забрать результат, если генерация не успела за 25 секунд:

```json
{"task_id": "3797"}
```

Вторая картинка по тому же промпту намеренно:

```json
{"prompt": "рыжий кот на подоконнике", "force_new": true}
```
